# Inventoros 2.1.0

Inventoros 2.1.0 brings a full-height operational workspace, more capable
warehouse workflows and a verified application-wide design/localization pass.

## Workspace, usability and performance

- Tables fill the available workspace while filters, pagination and actions
  stay reachable. Every application table supports its own scrolling and an
  expanded full-table view. Legal links appear on one line below table controls.
- Refined dashboard hierarchy, navigation and light/dark surfaces preserve the
  established Inventoros identity. Responsive forms, dialog focus, keyboard
  navigation and permission-denied recovery are improved.
- Notifications load actual unread records, show retryable failures and follow
  a destination after the read update succeeds. Rejected delete/approval actions
  retain their confirmation, validation reason and entered review notes.
- Core and bundled plugin interfaces cover all 14 supported languages, including
  Arabic direction, reactive labels and regional dates/numbers. Loading only the
  selected language reduces initial compressed application JavaScript by about
  73%; unselected languages are not prefetched in the background.
- Measured list-query indexes and redundant-index cleanup improve tenant,
  warehouse, relationship and ordering access paths on MySQL and PostgreSQL.
- Production packages exclude browser harnesses and credential-bearing QA
  seeders while retaining required production seeders.

The UI audit exercised seven viewport widths and all supported languages.
See the [audit and verification limits](https://github.com/Inventoros/Inventoros/blob/v2.1.0/UI_UX_AUDIT.md).
Invoice PDF localization/font support and exceptional provider diagnostics remain
documented gaps; configured tax labels and immutable invoice snapshots retain
their recorded values.

## Inventory and counting

- Stock by warehouse, variant bins, warehouse access controls and prepared,
  shipped and received transfer stages keep warehouse quantities explicit.
- Audit lines count exact variants and locations. Accepted counts and recounts
  retain their quantities, notes, authors and sequence in history.
- Optional supervisor variance approval binds a decision to a specific count.
  Recount requests preserve evidence and invalidate old offline revisions;
  audit completion waits for required reviews.
- Large audits load 25, 50 or 100 lines per page. Scanners resolve across the
  entire audit, saved offline drafts can sync from another page, and progress
  and completion confirmations use whole-audit totals.
- Variant replenishment rules set warehouse thresholds and targets, supplier
  costs, minimum orders and pack multiples. Planning counts outstanding inbound
  stock before creating a draft PO. Receiving uses its selected warehouse bin.
  Daily automatic draft creation is optional and disabled by default.
- Administrator stock reset uses an expiring confirmed preview, a dedicated
  queue and durable results. Authorization and the approved snapshot are checked
  again by the worker; an atomic ledger write-off preserves the catalog and
  transaction history.
- Reservations protect available stock across inventory workflows. Batch expiry
  reporting, variant-aware custom reports, tracked reconciliation, production
  allocation order and warehouse-bound report access are improved.

## Storage, billing and integrations

- Local or S3-compatible upload storage can be configured per installation.
  Installation administrators can verify private write/read/delete operations
  from File storage settings. Existing files retain their original disk.
- Tax Billing supports configurable country tax profiles, local identifier
  labels and additive components, plus an India domestic GST profile and
  retained variant size-matrix invoices. It does not automate every country's
  tax rules, filings or government e-invoicing. See the
  [plugin's supported scope](https://github.com/Inventoros/Inventoros/blob/v2.1.0/plugins/tax-billing/README.md).
- External payment-record imports are audited. Organization currency defaults,
  plugin customer fields, runtime application branding and integration hooks
  are included in this update.
- Supported dependencies were refreshed, dependency auditing covers every
  severity, and release packaging excludes Docker Compose deployment files.

The separately distributed Shopify plugin has its own version and release
process. Installing this core release does not install or activate that plugin.

## Upgrade and operations

PHP requirements remain 8.4.1 or newer, with PHP 8.4 and 8.5 supported. MySQL
8.0+, PostgreSQL 13+ and development SQLite remain supported. Follow the
[2.1 upgrade instructions](https://github.com/Inventoros/Inventoros/blob/v2.1.0/UPGRADE.md) and
[deployment checklist](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/releases/2.1.0-checklist.md).

Keep the scheduler running every minute and restart long-lived workers after
the upgrade. The administrator reset queue uses its own database connection
and `inventory-resets` queue, even when ordinary application jobs use another
backend. See [reset operation details](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/ADMIN_STOCK_RESET.md).

Useful feature guides:

- [Variance approval and recounts](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/STOCK_AUDIT_VARIANCE_REVIEW.md)
- [Large stock audits and REST compatibility](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/LARGE_STOCK_AUDITS.md)
- [Variant replenishment](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/VARIANT_REPLENISHMENT.md)
- [External storage](https://github.com/Inventoros/Inventoros/blob/v2.1.0/docs/external-storage.md)

Legacy REST audit detail responses retain all items by default. New clients can
use paginated item endpoints or `include_items=0` for metadata and summary.
Optional approval and replenishment settings do not change existing audits or
begin automatic purchasing when the application is upgraded.
