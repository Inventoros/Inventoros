# Inventoros 2.6.2

This release adds preorders: a product that is not out yet can take orders
before its release date, and those orders wait to ship until it arrives. It
also makes the stock adjustment form searchable and fixes bugs found in an
audit of 2.6.1. The full list is in the
[changelog](https://github.com/Inventoros/Inventoros/blob/v2.6.2/CHANGELOG.md).

## Preorders

- **Setting it up:** give a product a **Release date** on its form, or send
  `release_date` (`YYYY-MM-DD`) over the REST API. Until that date the
  product is a preorder.
- **Taking orders:** while **Allow backorders** is on under Settings >
  Organization > Backorders, a preorder can be ordered past its stock even
  if **Allow backorder** is not ticked on the product. The shortfall goes on
  backorder and is filled the usual way when stock arrives.
- **Release date as a street date:** an order that includes a preorder
  cannot ship before the release date, even if the stock arrives early. If
  it has several preorder items, it waits for the latest date. Creating a
  shipment, and setting the status to shipped or delivered by any route, is
  refused until then, and an order cannot be created as shipped or delivered.
- **On screen:** the order page shows the date in a banner and on each
  preorder line, the shipping panel explains the hold, and the edit form
  disables the shipped and delivered statuses until release.
- **API:** products return `release_date` and `is_preorder`. Orders and their
  lines return `preorder_release_date` when their items are loaded.
- On its release date the product behaves like any other product. Clearing
  the date releases it straight away.

See [backorders and preorders](https://github.com/Inventoros/Inventoros/blob/v2.6.2/docs/site/sections/backorders.md).
([#453](https://github.com/Inventoros/Inventoros/issues/453), [#459](https://github.com/Inventoros/Inventoros/pull/459))

## Searchable product picker on stock adjustments

The stock adjustment form uses the same product picker as orders, purchase
orders and stock transfers. Type to filter by product name, SKU or barcode,
including a variant's title, SKU or barcode. The barcode scan button sits
beside the picker.
([#456](https://github.com/Inventoros/Inventoros/issues/456), [#458](https://github.com/Inventoros/Inventoros/pull/458))

## Fixes

- An order created as cancelled no longer takes stock that was then lost
  for good.
- Receiving a return restocks a product deleted since the sale, and
  completing a stock audit no longer fails when a counted product was
  deleted.
- A product import that leaves a column out keeps that field on existing
  products instead of blanking it.
- Permissions granted through a role's permission sets now count everywhere
  `hasPermission()` does, including the navigation, API token abilities and
  the check that stops someone managing a user who holds more than they do.
- REST and GraphQL order updates are atomic, malformed REST order filters no
  longer return a 500, and GraphQL returns access refusals and missing
  records as client errors.
- Stock transfer variant ids are checked against the caller's organization.
- A purchase order total too large to store, and a manual exchange rate like
  `.5`, are validation errors instead of a 500.
- The stock adjustment value threshold is compared in the organization's
  currency, and resaving an approved draft purchase order's lines unchanged
  keeps the approval.

([#457](https://github.com/Inventoros/Inventoros/pull/457))

## Upgrade

Back up the database, `.env` (with `APP_KEY`), uploads and installed plugins
first. Requirements are unchanged from 2.6.1.

### Migrations

One migration adds a nullable column, so existing rows need no changes:

- `products.release_date`, null

### How to update

- **Docker and Coolify:** pull the 2.6.2 image and recreate the app, worker and
  scheduler. The app runs the migrations on start. Never use the in-app updater
  in a container.
- **Linux installer:** `sudo bash install.sh --version 2.6.2`.
- **cPanel, Composer and other in-app updates:** Admin > Update.
- **Source (git):**

  ```bash
  git fetch --tags && git checkout v2.6.2
  composer install --no-dev --optimize-autoloader
  npm ci && npm run build
  php artisan migrate --force
  php artisan optimize
  php artisan queue:restart
  ```

Coming from 2.6.0 or earlier, read the
[2.6.1 upgrade notes](https://github.com/Inventoros/Inventoros/blob/v2.6.2/docs/releases/2.6.1.md#upgrade)
first.
