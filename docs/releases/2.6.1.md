# Inventoros 2.6.1

This release adds backorders: a sales order can be accepted for more than is
on hand and held from shipping until the stock arrives. Backorders are off
until an administrator turns them on, so nothing changes for an organization
that does not use them. The full list is in the
[changelog](https://github.com/Inventoros/Inventoros/blob/v2.6.1/CHANGELOG.md).

## Backorders

- **Turning it on:** tick the master switch under Settings > Organization >
  Backorders, then **Allow backorder** on each product that may be sold short.
  An optional default ticks the product toggle on new products. Over the REST
  API, products accept and return `allow_backorder`.
- **Placing an order:** a short line is split into units fulfilled from stock
  and units on backorder. Only the fulfilled units leave stock. The order shows
  a banner and each short line shows its split. The web app, REST, GraphQL and
  MCP all follow the same rule.
- **Shipping together:** an order with units on backorder cannot be shipped.
  Creating a shipment, and setting the status to shipped or delivered by any
  route, is refused until every line is fulfilled.
- **When stock arrives:** outstanding backorders for the product are filled
  oldest order first. This happens on purchase order receipts and any other
  stock increase, from the **Fulfil backorder** button on the order (needs
  `manage_stock`), and from the `inventory:reconcile-backorders` sweep every
  fifteen minutes.
- **Cancel, reject, delete and edit:** only the units that left stock are
  returned. Editing recomputes the split. If backorders have been turned off
  since, an edit keeps the units already on backorder but cannot add more.
- The orders list has a Backordered filter. Pick lists show only the units
  in stock, and order webhooks include `backordered_at` and each line's
  `quantity_fulfilled` and `quantity_backordered`.

Not covered yet: preorders scheduled by a release date, drafting a supplier
purchase order for the shortfall, and shipping the available part of an order
early.

See [backorders](https://github.com/Inventoros/Inventoros/blob/v2.6.1/docs/site/sections/backorders.md).
([#453](https://github.com/Inventoros/Inventoros/issues/453), [#454](https://github.com/Inventoros/Inventoros/pull/454))

## Upgrade

Back up the database, `.env` (with `APP_KEY`), uploads and installed plugins
first. Requirements are unchanged from 2.6.0.

### Migrations

Three migrations add columns. Each has a default, so existing rows need no
changes:

- `products.allow_backorder`, false
- `order_items.quantity_backordered`, 0
- `orders.backordered_at`, null

### Scheduler

`inventory:reconcile-backorders` runs every fifteen minutes. An install that
already runs `php artisan schedule:run` every minute picks it up without
changes.

### How to update

- **Docker and Coolify:** pull the 2.6.1 image and recreate the app, worker and
  scheduler. The app runs the migrations on start. Never use the in-app updater
  in a container.
- **Linux installer:** `sudo bash install.sh --version 2.6.1`.
- **cPanel, Composer and other in-app updates:** Admin > Update.
- **Source (git):**

  ```bash
  git fetch --tags && git checkout v2.6.1
  composer install --no-dev --optimize-autoloader
  npm ci && npm run build
  php artisan migrate --force
  php artisan optimize
  php artisan queue:restart
  ```

Coming from 2.5.0 or earlier, read the
[2.6.0 upgrade notes](https://github.com/Inventoros/Inventoros/blob/v2.6.1/docs/releases/2.6.0.md#upgrade)
first.
