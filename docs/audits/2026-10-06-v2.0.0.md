# Codebase Health Report: Inventoros 2.0.0

Date: 2026-10-06. Baseline: `2628809c`, compared with the last published release,
`v1.0.8`. Scope: architecture, security, performance, quality, reliability and
production edge cases, with focused implementation and regression tests for
confirmed release blockers. The existing archived roadmap is historical;
current code, tests, changelog and the October design documents determine what
ships in this release.

## Executive summary

The core has substantial automated coverage, including SQLite, MySQL,
PostgreSQL and browser checks. The audit found release blockers around
installation-wide authorization, stale stock-operation transitions, update
recovery, queue lifetimes and Docker persistence. These were fixed in the
release candidate. Remaining technical debt is moderate: large-data workflows,
retention, build-tool dependencies and planned reservation support.

The three highest-impact fixes are restricting installation restore/update
access to the owning organization, preventing completed stock operations from
being reopened by stale requests, and keeping a failed restore in maintenance
instead of exposing a partially restored application.

## P0 / P1: resolved for this release

| Finding and impact | Change and evidence |
|---|---|
| A tenant admin could update, restore or delete backups for the entire installation. | `UpdateAdministration`, `EnsureUpdateAdministrator` and the update route group enforce the existing installation-owner organization, base-admin role and `manage_organization`. The settings link uses the same decision. `UpdateControllerTest` exercises another tenant and configured ownership. |
| Stale transfer, return, work-order or stock-audit requests could reopen completed work, repeat stock movements or alter completed count evidence. | The transition services reload and lock the current row before checking state. Deterministic stale-model tests cover finished transfers, returns, work orders and audits. |
| Queue reservations expired after 90 seconds although imports, exports and reports may run for 600 seconds. A second worker could execute the same job concurrently. | Database, Redis and Beanstalkd defaults are 660 seconds. `QueueReservationTimeoutTest` compares reservations against every declared job timeout. Systemd and Docker worker shutdown grace is also 660 seconds. SQS visibility and existing overrides are documented in `UPGRADE.md`. |
| Updater rollback backups were taken while new work was still accepted, and failed rollback brought the site online. | `UpdateService` downloads and validates first, enters maintenance before backup, restarts workers on successful recovery and stays down if restoration fails. Ordering and failure-path regression tests were added. Operators must drain already-running requests/jobs before updating; maintenance does not cancel them. |
| Installed Docker plugins existed only inside the web container, disappeared on recreation and were absent from workers. | Shared `plugins` and `plugin-assets` volumes are mounted by all PHP services. The image creates writable mount points. CI checks persistence and non-root access using a second container after the web container is removed. Existing installations must migrate files before adding these volumes. |
| Low-stock reports hydrated every match before applying the export cap and queried warehouse balances per product. | SQL limits hydration, summaries cover the full matching set and warehouse balances are loaded in a batch. The UI reports truncation. `FixedReportExportsTest` covers limits and summary consistency. |

## Other defects resolved

- Work orders moved product totals without recording serials, batches or
  variants. Unsupported tracked products and virtual kits now fail validation
  before inventory changes, on both web and REST surfaces and for legacy work
  orders. See `WorkOrderIntegrityTest`.
- Scheduled reports recheck active status, recipient membership, current email
  and report permissions at delivery, so queue delays cannot bypass revocation.
  See `ScheduledReportsTest`.
- Plugin-filtered queries now group OR predicates before adding tenant scope;
  unsafe union builders fall back to a scoped query. This guards accidental
  query widening; installed PHP plugins remain trusted code.
- Inter-company variant adjustment webhooks retain the product from the
  adjustment's organization after the temporary organization context ends.
- Cycle counts can select a creator through organization membership even when
  nobody has that organization as their home. Location-scoped draft counts
  snapshot the selected bin rather than the product total.
- Vue and source-map-js production advisories were fixed in `2628809c`.
  A scoped `shell-quote` override now removes the critical development-tool
  command-injection advisory without changing the development runner's major
  version.
- Release publication checks that the version file and release notes exist
  and match. Tagged releases require a signing key matching the public key
  shipped to users. Manual Docker build checks receive a usable image tag.

## P3: backlog

- Split the large frontend entry bundle using measured route/component loading
  needs. Production builds succeed but emit the existing large-chunk warning.
- Continue consolidating duplicated web/API business logic into services where
  it prevents behavior drift; the shared work-order start is one example.
- Keep feature documentation aligned with shipped behavior. Barcode scanning
  permission names, browser session authentication and order scanning were
  corrected during this audit.

## Cross-cutting themes

Tenant permissions do not imply authority over an entire installation.
Organization context must also survive queued and after-commit work. Likewise,
checking a model's status before acquiring a database lock is insufficient when
other requests can change it. These boundaries now have additional regression
coverage.

## If I owned this codebase

2. Benchmark and bound whole-inventory counts on production-sized fixtures.
3. Upgrade the CSS build toolchain with visual comparisons.
4. Rehearse populated legacy upgrades on MySQL and PostgreSQL.
5. Implement reservations as a separate inventory contract before dependent
   rental/picking plugins promise it.

## Verification

An isolated populated SQLite upgrade from `v1.0.8` passed: 63 legacy migrations
plus 46 new migrations, preserving organization/user, custom role, API token,
products, a variant, delivered order and order lines. Stock and totals were
unchanged; currency, historical payment status, estimated costs and tenant
bindings were backfilled as expected. SQLite reported no foreign-key violations
and repeating migrations made no changes.

Release verification results are recorded with the release pull request and
GitHub Actions runs. Checks include PHP tests on all three database engines,
JavaScript tests, frontend and example-plugin builds, browser tests, production
dependency audits, cPanel package verification and Docker smoke/persistence
checks. The release is published only after these checks pass.
