# v2.0.0 release audit

Audited 6 October 2026 against `2628809c`, compared with v1.0.8 (the last
published release). The old roadmap in `docs/archive` is out of date, so for
this pass we went by the code, the tests, the changelog and the October design
docs.

## Summary

Test coverage is in good shape: the PHP suite runs on SQLite, MySQL and
PostgreSQL, and the main flows have browser tests. Even so, the audit turned up
a handful of things we weren't willing to ship: tenant admins could reach
installation-wide update and backup controls, stale requests could reopen
finished stock operations, a failed rollback brought the site back online half
restored, queue jobs could run twice, and Docker lost installed plugins when
the web container was recreated. All of those are fixed in 2.0.0.

What's left is mostly larger work: reservations, tracked work orders, big
cycle counts, export cleanup and the Tailwind 3 build tooling.

## Fixed before release

**Installation-wide update and backup access.** Any tenant admin could update
the app or restore and delete backups for the whole installation. The update
routes now go through `UpdateAdministration` and `EnsureUpdateAdministrator`,
which require the installation-owner organization, the base admin role and
`manage_organization`. The settings link uses the same check.
`UpdateControllerTest` covers another tenant and a configured owner.

**Stale state transitions.** A stale transfer, return, work order or stock
audit request could reopen finished work, repeat stock movements or change a
completed count. The transition services now reload and lock the row before
checking its state, with stale-model tests for each.

**Queue reservation timeout.** Reservations expired after 90 seconds, but
imports, exports and reports can run for up to 600, so a second worker could
pick up the same job. Database, Redis and Beanstalkd now default to 660
seconds, and so do the systemd and Docker worker shutdown grace periods.
`QueueReservationTimeoutTest` checks every job's timeout against the
reservation. SQS visibility timeouts and existing overrides are covered in
`UPGRADE.md`.

**Updater rollback.** The rollback backup was taken while the app was still
taking requests, and a failed rollback put the site back online.
`UpdateService` now downloads and validates first, enters maintenance mode
before the backup, restarts workers after a successful recovery and stays in
maintenance if the restore fails. Operators still need to let running requests
and jobs finish before updating, since maintenance mode doesn't cancel them.

**Docker plugins.** Installed plugins only existed inside the web container,
so they vanished on recreate and never reached the workers. `plugins` and
`plugin-assets` are now shared volumes on every PHP service, and CI checks
that they survive removing the web container. Existing installs need to move
their plugin files into the volumes before switching over.

**Low-stock report.** It loaded every matching product before applying the
export cap and looked up warehouse balances one product at a time. The limit
is applied in SQL now, the summary still covers the full result set, balances
load in one query and the UI says when results were truncated
(`FixedReportExportsTest`).

Smaller fixes:

- Work orders were moving product totals without recording serials, batches
  or variants. Tracked products and virtual kits are now rejected before any
  stock changes, on the web, in the REST API and for older work orders
  (`WorkOrderIntegrityTest`).
- Scheduled reports re-check that the report is active, the recipient is still
  a member with the right permissions, and their current email address at send
  time, so a queued report can't outlive a revoked permission
  (`ScheduledReportsTest`).
- Plugin query filters now group OR conditions before the tenant scope is
  added, and union queries fall back to a scoped query. This stops accidental
  widening; PHP plugins are still trusted code.
- Inter-company variant adjustment webhooks keep the right product after the
  temporary organization context ends.
- Cycle counts can pick a creator through organization membership even if no
  one has that organization as their home. Location-scoped drafts snapshot the
  selected bin instead of the product total.
- Vue and source-map-js advisories were patched in `2628809c`, and a scoped
  `shell-quote` override removes the critical command-injection advisory in
  the dev tooling without a major version bump.
- Publishing a release now checks that `VERSION` and the release notes exist
  and agree, tagged releases need a signing key that matches the public key we
  ship, and manual Docker builds get a proper image tag.

Lower priority:

  Split it where measurements show it helps.
- Keep moving logic that's duplicated between web and API controllers into
  services (the shared work-order start is a good example).
- Keep the feature docs in step with the code. This pass corrected the barcode
  scanning permission names, browser session auth and order scanning docs.

## Lessons

Being an admin of a tenant shouldn't mean being an admin of the installation.
Organization context has to survive into queued and after-commit work. And
checking a row's status before taking the lock isn't enough when another
request can change it in between. All three now have regression tests.

## Verification

We ran a populated SQLite upgrade from v1.0.8 in isolation: 63 old migrations
plus 46 new ones, with an organization and user, a custom role, an API token,
products, a variant, and a delivered order with lines. Stock and totals were
unchanged after the upgrade, and currency, historical payment status,
estimated costs and tenant bindings were backfilled correctly. SQLite reported
no foreign key violations, and running the migrations again changed nothing.

Results for the release itself are on the release pull request and its
GitHub Actions runs: PHP tests on all three databases, JavaScript tests,
frontend and example-plugin builds, browser tests, production dependency
audits, cPanel package verification and the Docker smoke and persistence
checks. The release only goes out once those pass.
