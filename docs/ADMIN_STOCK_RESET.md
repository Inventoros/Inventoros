# Administrator stock reset

Administrators can use **Products > Reset stock to zero** for the active organization. Review the counts, enter a reason, the current password and `ZERO STOCK`. The preview expires after ten minutes and any stock change requires a fresh preview. Submission queues an operation and opens its status page. The worker checks the approved stock snapshot and the administrator's current membership and permissions again before writing. Changed stock or lost access causes a failed result without resetting stock; review a new preview to try again.

This affects the entire organization, including inactive and soft-deleted products, and retains catalog records and transaction history. Product and variant totals and bins are corrected through the stock ledger; available serials are retained as written off and batch balances are zeroed, with audit records. Existing sold, consumed and transferred serials remain unchanged. The operation UUID ties the result to its ledger entries and audit records. All stock changes and the completed result commit together; a failure rolls them back and records a failed result separately.

Finish or cancel open transfers, in-progress stock counts and production, and release active reservations before resetting. This action does not disable integrations: pause external stock imports before resetting if they could restore quantities. No database tables are truncated.

Operations use the application database's `jobs` table and the dedicated `inventory-resets` queue, independently of the ordinary queue backend. The existing minute-by-minute `php artisan schedule:run` cron drains this queue automatically. A deployment without that scheduler must run `php artisan queue:work inventory-resets --queue=inventory-resets --timeout=900 --tries=1` under its worker supervisor. Keep the supervisor's shutdown grace period above 900 seconds. The queue reservation lasts 1,200 seconds. If a worker is killed, the next worker fails its abandoned operation after the reservation expires; it does not execute it twice.

The default budget is 5,000 affected stock records across products, variants, bins, available serials and batches. Zero-only records do not consume this budget. `INVENTOROS_STOCK_RESET_MAX_RECORDS` can change it to suit the worker's memory and transaction timeout. The operation streams the catalogue in bounded batches, but it still locks the organization's stock for the duration of the atomic write-off. Schedule large resets during maintenance. Invalid cross-organization inventory relationships block the operation until repaired.
